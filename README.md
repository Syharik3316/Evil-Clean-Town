# Чистый берег

Платформа популяризации экологического мониторинга ДЗЗ и волонтёрских уборок побережья.
Спутниковый мониторинг (карта до/после) остаётся смысловым центром продукта — уборочные
мероприятия жёстко привязаны к участкам побережья (`CoastlineSite`), а вся волонтёрская
инфраструктура (регистрация с верификацией, роли, тикеты, курсы, геймификация) обслуживает
эту историю.

- **Backend:** Python, FastAPI, SQLAlchemy 2.0 (async), Alembic, PostgreSQL, JWT-аутентификация
- **Frontend:** простой multi-page vanilla HTML/CSS/JS (без сборки) на дизайн-системе
  Broadsheet (`frontend/css/style.css` — токены и компоненты, исходник дизайна в
  `newfront/`), **Яндекс.Карты во всех разделах с картами** (`frontend/js/yamaps.js` —
  общая обёртка: карты, метки, радиус чекина, наложение снимков ДЗЗ) плюс Яндекс Suggest
  API для адресов, PWA-манифест, чистые адреса без `.html` (см. `nginx/nginx.conf`)
- **Деплой:** Docker Compose (PostgreSQL + backend + nginx + Grafana)

## Роли и основные страницы

Каждая страница сама адаптирует содержимое под роль — набор пунктов меню полностью
разный для каждой роли (см. `frontend/js/nav.js`):

| Роль | Страницы |
|---|---|
| Волонтёр | `/events` (календарь), `/event?id=…` (страница мероприятия: подробности проведения, точка сбора на Яндекс.Карте с радиусом гео-чекина, заявка и подтверждение участия), `/lessons` (прохождение курсов), `/reports` (отправка репортов о мусоре), `/leaderboard`, `/notifications`, `/profile` (баллы, ачивки, верификация возраста, рамка аватара, соц-шеринг) |
| Организатор | `/organizer` (создание мероприятий на карте Яндекс, заявки участников, роли, бонусные баллы), `/lessons` (создание/модерация своих курсов), `/reports` (модерация репортов волонтёров) |
| Администратор | `/tickets` (модерация мероприятий и курсов с обязательной причиной отказа и картой точек сбора), `/admin` (мониторинг: KPI фонда, **окно Grafana** с дашбордом в iframe, карта активности, очередь модерации), `/reports` (модерация репортов) |

Регистрация — двумя путями: обычная (логин/email/пароль + код подтверждения на почту)
и организаторская (через ИНН, кнопка «Я организатор» на `/register`). Верификация
возраста — кнопка «Госуслуги» (интеграция не подключена, эндпоинт возвращает 501 до
заполнения `GOSUSLUGI_*` в `.env`) плюс работающая «Ручная верификация».

## Структура проекта

```
backend/        FastAPI-приложение (app/), Alembic-миграции, тесты (pytest)
frontend/       Статические HTML/CSS/JS-страницы (дизайн-система Broadsheet)
newfront/       Исходник дизайна (design canvas), по которому свёрстан frontend/
nginx/          Конфиг reverse-proxy (отдаёт frontend/, проксирует /api и /static)
docker-compose.yml
.env.example    Шаблон переменных окружения — скопируйте в .env и отредактируйте
```

## Быстрый старт (локально или на VDS)

1. Установите Docker и Docker Compose (`docker compose version`).
2. Скопируйте `.env.example` в `.env` и задайте свои значения — как минимум смените
   `POSTGRES_PASSWORD`, `JWT_SECRET_KEY`, `GF_SECURITY_ADMIN_PASSWORD` и
   `GRAFANA_DB_PASSWORD` на случайные строки:

   ```bash
   cp .env.example .env
   ```

   Также в `.env` можно указать `SMTP_*` для реальной отправки писем с кодом подтверждения
   email — если оставить `SMTP_HOST` пустым, backend не отправляет письма, а пишет код в
   свой лог (`docker compose logs backend`), чего достаточно для локальной проверки.
   `GOSUSLUGI_*` — заготовка интеграции с Госуслугами, не требует заполнения (пока пусто,
   кнопка в профиле показывает «интеграция в разработке», и работает ручная верификация).

3. Соберите и запустите весь стек:

   ```bash
   docker compose up -d --build
   ```

   При первом запуске backend-контейнер автоматически:
   - применит Alembic-миграции (`alembic upgrade head`), включая создание read-only
     Postgres-роли `grafana_reader` для дашбордов,
   - засеет справочник учреждений (школы/вузы/колледжи Ростова-на-Дону для выбора
     волонтёром своей команды/школы в профиле) — это происходит всегда, независимо от
     `SEED_ON_STARTUP`, и безопасно повторно запускать (идемпотентно по названию,
     см. `backend/app/db/seed_institutions.py`),
   - засеет демо-данные (участки берега, обучающие курсы, ачивки, демо-мероприятия,
     три демо-аккаунта ролей volunteer/organizer/admin), если `SEED_ON_STARTUP=true`
     в `.env` и БД пустая.

4. Откройте `http://<адрес-сервера>/` в браузере, статистику активности — на
   `http://<адрес-сервера>:3000` (Grafana; логин `admin`, пароль — значение
   `GF_SECURITY_ADMIN_PASSWORD` из вашего `.env`; дашборд «Активность пользователей —
   Чистый берег» уже провизирован).

### Демо-аккаунты

Если `SEED_ON_STARTUP=true`, seed-скрипт создаёт по одному демо-аккаунту на каждую роль
(volunteer/organizer/admin) — логины и пароли см. в `backend/app/db/seed.py` (не
публикуются здесь намеренно). Вход выполняется по **логину** (`username`), не по email.

**Перед реальным использованием смените эти пароли или удалите демо-аккаунты, а также
выставьте `SEED_ON_STARTUP=false`** в `.env` и перезапустите `docker compose up -d`,
чтобы случайный рестарт контейнера не пытался повторно засеять демо-данные (хотя seed и
так безопасно пропускает себя, если в БД уже есть пользователи).

## Развёртывание на VDS (домен + TLS + внешний nginx)

Стек в `docker-compose.yml` слушает только `127.0.0.1:80` изнутри Docker — TLS и домен
терминирует **внешний** nginx, установленный прямо на VDS (не в контейнере), который
проксирует запросы в docker-compose. Так проще всего продлевать сертификаты Let's
Encrypt и не переизобретать конфиг внутри `nginx/nginx.conf` (тот отвечает только за
раздачу фронтенда и проксирование на backend/uploads).

1. **Домен**: пропишите A-запись домена на IP вашего VDS.

2. **Порт docker-compose наружу**: в `docker-compose.yml` у сервиса `nginx` замените
   `ports: ["80:80"]` на `ports: ["127.0.0.1:8080:80"]` — так контейнерный nginx будет
   доступен только с самого сервера, а не напрямую снаружи (снаружи будет виден только
   внешний nginx на 80/443).

3. **Установите nginx и certbot на сам VDS** (не в Docker), например на Ubuntu/Debian:

   ```bash
   sudo apt update && sudo apt install -y nginx certbot python3-certbot-nginx
   ```

4. **Конфиг внешнего nginx** (`/etc/nginx/sites-available/chistybereg`, затем
   `ln -s` в `sites-enabled` и `nginx -t && systemctl reload nginx`):

   ```nginx
   server {
       listen 80;
       server_name your-domain.ru;

       location / {
           proxy_pass http://127.0.0.1:8080;
           proxy_set_header Host $host;
           proxy_set_header X-Real-IP $remote_addr;
           proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
           proxy_set_header X-Forwarded-Proto $scheme;
       }
   }
   ```

5. **Получите сертификат** — certbot сам допишет `listen 443 ssl`, редирект с 80 на 443
   и настроит автообновление (systemd-таймер `certbot.timer` уже входит в пакет):

   ```bash
   sudo certbot --nginx -d your-domain.ru
   ```

6. **Проверьте**: `https://your-domain.ru/` должен отдавать фронтенд, `https://your-domain.ru/api/health`
   — `{"status":"ok"}`. Браузеры требуют HTTPS для `navigator.geolocation` на внешних
   доменах (гео-чекин на мероприятиях, определение координат в репортах) — без TLS эти
   функции просто не будут работать за пределами `localhost`.

7. **Grafana** (порт 3000) встроена в `/admin` сайта через `<iframe>` (см. `js/admin.js`,
   `js/config.js`), поэтому браузер администратора должен доставать до порта 3000
   напрямую — **не закрывайте его файрволом**, если хотите, чтобы дашборд на `/admin`
   работал. Ради бесшовного встраивания без отдельного логина включён анонимный доступ
   уровня Viewer (`GF_AUTH_ANONYMOUS_*` в `docker-compose.yml`) — это делает сам дашборд
   (агрегированную статистику, без email/паролей/личных данных) доступным всем, кто
   достучится до порта 3000, а не только вашим админам. Если это неприемлемо для вашего
   случая — либо закройте порт 3000 в файрволе и потеряйте встраивание (дашборд на
   `/admin` не откроется, но `python -m app.db.seed`/API продолжат работать), заменив
   секцию на `/admin` обратно на статические карточки, либо ограничьте доступ к порту
   3000 на уровне файрвола/VPN только доверенной сетью.
   
   Если сайт задеплоен на HTTPS (см. п. 5), а Grafana остаётся на голом HTTP:3000 —
   браузер заблокирует именно `<iframe>` как mixed content (сама вкладка со страницей
   отработает, просто вместо дашборда будет пусто), но ссылка-фолбэк под iframe
   («Откройте дашборд напрямую») всё равно откроется в новой вкладке, так как переход по
   ссылке mixed-content не блокируется. Чтобы iframe тоже работал под HTTPS, заведите
   Grafану под TLS так же, как основной сайт — отдельный поддомен
   (`grafana.your-domain.ru`) с ещё одним `certbot --nginx -d grafana.your-domain.ru`,
   и поменяйте `GRAFANA_PORT` на `443`/уберите порт из `js/config.js`, если понадобится.

8. **Яндекс.Карты/Suggest** (`frontend/js/config.js`): ключи привязаны в кабинете
   developer.tech.yandex.ru к конкретным доменам/рефererам — при смене домена зайдите
   в кабинет и добавьте туда новый домен, иначе карта и подсказки адреса перестанут
   работать.

## Разработка

### Backend без Docker

```bash
cd backend
python -m venv .venv && . .venv/Scripts/activate   # Windows Git Bash
pip install -r requirements.txt
alembic upgrade head
python -m app.db.seed   # опционально
uvicorn app.main:app --reload
```

По умолчанию (без `DATABASE_URL` в окружении) используется локальный SQLite-файл — этого
достаточно для разработки API без Postgres.

### Тесты

```bash
docker compose run --rm --entrypoint pytest backend -v
```

Тесты используют in-memory SQLite и не трогают вашу основную БД (миграции Alembic в них
не участвуют — схема создаётся напрямую из моделей). Покрыты: регистрация с email-кодом
и организаторская регистрация через ИНН, ручная/Госуслуги-заглушка верификация возраста,
подача заявки → одобрение организатором → гео-чекин на мероприятие (с гейтами по
возрасту/базовому курсу/курсу-условию), админ-тикеты (репорты, мероприятия с
edit-and-approve, курсы) с уведомлениями, авторство и модерация курсов, начисление баллов
организации и «огонёк» участия, лидерборд по участникам/организациям/регионам.

### Миграции

```bash
docker compose run --rm --entrypoint alembic -v "$(pwd)/backend/alembic/versions:/app/alembic/versions" backend revision --autogenerate -m "описание изменений"
docker compose restart backend   # применит новую миграцию через entrypoint.sh
```

### Frontend отдельно (без backend)

```bash
cd frontend
npm install
npm run dev   # статика на http://localhost:5173, но API-запросы будут падать без backend/nginx
```

Полноценная работа фронтенда (относительные пути `/api/...`) рассчитана на запуск через
nginx из `docker-compose.yml`, который проксирует API на тот же origin.

## Данные ДЗЗ

Реального доступа к API «СР Дата» / Sentinel Hub на момент разработки не было, поэтому
используется статичный демо-датасет: скрипт
`backend/app/db/seed_images.py` генерирует стилизованные снимки «до/после» для трёх
участков берега при первом запуске. Структура данных (`CoastlineSite` → `SatelliteLayer`
с полями `image_url`, `bounds`, `captured_at`) рассчитана на то, чтобы позже заменить
сгенерированные картинки на реальные тайлы/снимки через админский API
(`POST /api/v1/sites`, `POST /api/v1/sites/{id}/layers`) без изменения фронтенда.
